# 重构基线与行为合同

这是主计划阶段 0 的功能和验收清单，不是新的子蓝图。基线 `8c096ed`，数据全部为合成样本。

## 功能去向

| 旧能力 | 新入口 | 必须保留或明确改变的行为 |
| --- | --- | --- |
| 首次建库、解锁 | 锁定页 | 错误密码不写文件；取消留在锁定页，不自动退出 |
| 名称、平台、密钥、URL、模型、标签、备注、到期 | 列表摘要 + 详情 + 编辑面板 | 字段、Id、创建时间和日期语义兼容；编辑操作使用草稿 |
| 搜索六类文本 | 顶部搜索 | 名称/平台/模型/标签/备注/URL；不搜索密钥 |
| 新增、编辑、删除 | 新增按钮、详情与行菜单 | 保存成功后才公布修改；失败保留旧状态和可重试草稿 |
| 显示密钥 | 单条查看 | 限时显示，锁定和切换记录恢复掩码，忽略旧 ShowKeys 偏好 |
| 复制密钥和 URL | 行内密钥复制、详情 URL 复制 | 准确复制完整值；不因屏幕截断改变值；失败有反馈 |
| 剪贴板清理 | 系统服务 + 设置 | 定时器持续驱动，只清理自己的内容；失败有限重试 |
| 到期汇总 | 可点击状态筛选 | 14 天规则不变；“未设置到期日”对应 null；不再强制弹窗 |
| 手动/自动锁定 | 顶栏与会话服务 | 统一失效编辑草稿、明文和旧操作；解锁页可停留 |
| 浅色/深色 | 顶栏/设置 | 重新启动恢复主题，命令行 --dark 优先；不保存原型偏好 |
| 修改主密码 | 设置 | 先保存并验证再切换会话密码；失败不改变旧密码 |
| 低迭代库升级 | 解锁后应用流程 | 备份失败不升级；升级失败不阻止当前已验证的解锁 |
| 导出加密备份 | 数据管理 | 备份密码可独立设置；携带兼容偏好 |
| 合并导入 | 导入预览 | 按 Id 去重；不按名称擅自去重；不覆盖已有项 |
| 替换导入 | 导入预览与确认 | 可恢复备份成功后才允许覆盖 |
| 导入偏好 | 导入选项 | 恢复有效主题和时间设置，不恢复明文显示 |
| 明文 CSV | 数据管理的次级入口 | 保留列与转义；明确确认，不作为醒目主操作 |
| 便携/回退目录 | 启动上下文 | 默认与程序同目录，不可写时回退；--dir 优先 |
| 演示、自检、布局诊断 | 显式命令行 | 演示仅合成数据；诊断与正常使用路径隔离 |
| 查找/新增/锁定/主题快捷键 | 全局命令 | Ctrl+F/N/L/T；新增快捷键不抢文本编辑快捷键 |

## 冻结失败与并发规则

1. 所有库修改以候选快照提交。写入失败不修改当前已保存状态；UI 不先显示成功。
2. 保存队列同一时刻只执行一个提交。已经提交到磁盘的动作不伪装成可取消。
3. 锁定立即隐藏信息并使旧会话版本失效；后台完成只更新允许的磁盘结果，不能重新解锁界面。
4. 自动锁定清除未提交的敏感草稿；提前显示即将锁定提示。原型阶段只演示锁定状态，不宣称已经实现系统活动计时。
5. 替换导入备份失败则不覆盖；低强度升级备份失败则跳过升级并报告。
6. 原型在独立的 --prototype 入口中只使用内存合成记录，不能解析真实库目录、读写设置或自动保存。

## 多实例策略

源码检查未发现进程互斥或库级文件锁；当前不具备可证明的多实例安全写入。

目标策略冻结为：**同一规范化库路径同一时刻只有一个本机进程拥有写入会话；不同库路径可以分别运行。** 阶段 2 在读取/修改库前获取由宿主持有的独占锁文件句柄（同库目录内，FileShare.None），直到应用退出释放。后开的实例明确提示库已被使用，不尝试写入。锁文件残留不代表占用，以操作系统句柄是否成功获取为准。

路径经绝对路径规范化并统一大小写比较；junction/符号链接别名同样应命中同一目录锁文件。网络共享和不遵守锁协议的旧版本同时写入不在已保证范围内；新版不能控制外部旧程序。验收包括同路径、不同路径、异常退出后重新打开和锁文件创建失败。

## 固定兼容样本

`tests/ApiKeyManager.Tests/Fixtures/legacy-v1.json` 保存格式 v1 的加密字节（Base64）、合成密码、旧设置和预期字段。样本由独立 Node 标准加密库构造，随后由未改动的 Core 读取；固定盐和 nonce 仅用于这份公开测试夹具，生产加密仍使用随机值。

测试保护：旧记录缺少 ExpiresUtc 可读、中文/空密钥/相同名称不同 Id 不丢失、日期不被当成 UTC 转换、带设置的旧备份可读、当前格式重存字段一致、错误密码不写源样本、原有 CSV 和搜索语义。

原型不承担真实导入、持久保存、密码验证、真实剪贴板、自动锁定计时或可靠会话提交；这些由后续阶段实现并验证。界面明确标记演示状态，不能把模拟成功作为业务成功。
